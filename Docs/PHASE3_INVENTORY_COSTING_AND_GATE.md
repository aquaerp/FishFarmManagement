# المرحلة 3 — المخزون والتكلفة والتتبع التشغيلي

**بدء التنفيذ:** 15 يوليو 2026
**حالة المرحلة:** In Progress
**قرار البوابة G3:** غير مجتازة — اكتملت دورة المخزون والتتبع وتكلفة الإنتاج واعتمدت السياسة والعينة، وتبقى المطابقة المحاسبية.

## الحزمة الأولى المنفذة

- اعتماد المتوسط المرجح المتحرك طريقة تكلفة وحيدة في المحرك الأولي.
- منع LIFO في السياسة وعدم استخدامه في أي حساب أو ادعاء IFRS.
- إنشاء حركة مخزون كمسودة ثم اعتمادها بواسطة مستخدم مستقل.
- تحديث كمية الصنف وتكلفته والحركة وسجل التقييم داخل معاملة `Serializable` واحدة.
- منع الصرف الذي يؤدي إلى مخزون سالب قبل التحديث.
- حواجز SQLite تمنع إدخال أو تحديث كمية صنف إلى قيمة سالبة.
- حماية حركة المخزون المعتمدة من التعديل أو الحذف على مستوى SQLite.
- حفظ هوية المعتمد وسبب الاعتماد ووقته، مع حدث تدقيق محاسبي.
- حفظ لقطة تقييم بعد كل اعتماد بالكمية والتكلفة المتوسطة والقيمة الإجمالية.
- دقة ثلاث منازل للكمية ومنزلتين لتكلفة الوحدة والقيمة بالريال.
- اعتماد استلام المشتريات يحدث مع تحديث بنود أمر الشراء وإنشاء واعتماد وربط جميع حركات المخزون في معاملة واحدة؛ فشل أي بند يلغي العملية كاملة.
- التحقق المسبق يشمل الكمية المقبولة والجودة وسعر الوحدة والصنف النشط ومطابقة بند أمر الشراء ومنع تجاوز الكمية المطلوبة أو إعادة الإضافة.
- شاشة استلام المشتريات تحفظ مسودة كاملة البيانات ولا تنشئ حركة ناقصة أو تعدل الرصيد مباشرة، ثم يعرض تبويب الترحيل التشغيلي المسودات الجاهزة ليعتمدها مستخدم مستقل عبر المعاملة الذرية.
- شاشة حركات المخزون تنشئ مسودة موثقة بمرجع وسبب، ولا تغير الرصيد عند الحفظ أو التعديل أو الحذف؛ منشئ المسودة وحده يستطيع تصحيحها أو حذفها، ومستخدم مستقل وحده يستطيع اعتمادها وتطبيق المتوسط المرجح.
- الجرد الدوري والشامل يحتفظ بلقطة الرصيد والتكلفة عند البدء، ويلزم بعدّ كل صنف وسبب لكل فرق، ويمنع منشئ الجرد من اعتماده.
- اعتماد الجرد يرفض اللقطة القديمة إذا تحرك الرصيد أو التكلفة، ويطبق جميع الفروق وينشئ حركاتها وقيودها المرحّلة تلقائيًا داخل معاملة واحدة؛ فشل أي فرق يلغي الجميع.
- الجرد النهائي وبنوده محميان من التعديل أو الحذف على مستوى SQLite، مع ربط كل فرق بحركة المخزون والقيد الناتج.
- سجل التتبع يربط دفعة المورد المعتمدة بحركة الصرف والدورة والحوض، ثم بدفعة الحصاد وبند البيع المكتمل، مع استعلام أمامي وخلفي.
- لا يقبل استلام مشتريات دون رقم دفعة مورد، ولا يسمح تخصيص التتبع بتجاوز كمية الدفعة أو حركة الصرف أو وزن الحصاد أو كمية بند البيع.
- وحدات التتبع وتخصيصاتها غير قابلة للتعديل أو الحذف على مستوى SQLite، وتحتفظ بالمراجع والمستخدم وأحداث التدقيق.
- دفتر تكلفة الإنتاج يحمل استهلاك المدخلات بالتكلفة المرجحة والتكاليف المباشرة على الدورة والحوض دون ازدواج المصدر.
- النفوق الطبيعي يبقى ضمن الإنتاج تحت التشغيل ويتحمله الإنتاج السليم، بينما يفصل النفوق غير الطبيعي كخسارة بنسبة الكتلة النافقة إلى الكتلة الحية قبل الحدث.
- تحويل الأسماك بين الأحواض ينقل حصة متناسبة من تكلفة الإنتاج تحت التشغيل دون إنشاء ربح أو خسارة.
- دفعة الحصاد الموثقة تُرسمل بالتكلفة الفعلية في مخزون الأسماك الطازجة أو المجمدة وتدخل في متوسطه المرجح داخل معاملة واحدة.
- أحداث تكلفة الإنتاج غير قابلة للتعديل أو الحذف على مستوى SQLite، وتحفظ أساس القياس والمرجع والمستخدم ومسار التدقيق.

## أدلة التحقق

| الفحص | النتيجة |
|---|---|
| مجموعة الاختبارات الكاملة | 60/60 ناجحة |
| رصيد 10 وحدات × 20 ريال ثم استلام 10 × 10 | 20 وحدة بمتوسط مرجح 15 ريال |
| صرف 5 وحدات من المتوسط 15 | قيمة الحركة 75 ريال والرصيد 15 وحدة |
| اعتماد المنشئ لحركته | مرفوض |
| صرف 16 من رصيد 15 | مرفوض ولا تتغير الكمية |
| تعديل `CurrentStock` مباشرة إلى -1 | مرفوض على مستوى SQLite |
| تعديل حركة معتمدة | مرفوض على مستوى SQLite |
| سجل التقييم | لقطة WeightedAverage بعد كل اعتماد |
| استلام ببندين وأحد السعرين غير صالح | مرفوض؛ صفر حركات وصفر تغيير في المخزون ولا اعتماد للاستلام |
| تصحيح البند ثم اعتماد الاستلام | حركتان مرتبطتان، تحديث الصنفين وبنود الأمر، وتحويل أمر الشراء إلى مستلم |
| إعادة تنفيذ الاستلام نفسه | مرفوض وتبقى حركتان فقط |
| إنشاء وتعديل وحذف مسودة حركة | لا يغير المخزون، يقتصر على المنشئ، ويحفظ أحداث التدقيق الثلاثة |
| شاشة حركات المخزون بصلاحية Accountant | تُنشأ بنجاح وتعرض «حفظ مسودة» و«اعتماد وتطبيق» بدل التحديث المباشر للرصيد |
| جرد شامل بفائض وحدتين وعجز وحدتين | حركتا فرق معتمدتان، تحديث الرصيدين، وقيدان متوازنان مرحّلان تلقائيًا |
| محاولة منشئ الجرد اعتماده | مرفوضة، ولا تتغير الأرصدة |
| تغير الرصيد بعد لقطة الجرد | يُرفض الاعتماد وتبقى المسودة المقدمة بلا حركات أو قيود |
| فشل تقييم فرق لاحق بعد معالجة فرق سابق | تُلغى المعاملة كاملة؛ لا حركة ولا قيد ولا تغيير لأي رصيد |
| تعديل بند جرد معتمد مباشرة | مرفوض على مستوى SQLite |
| شاشة الجرد بصلاحية Accountant | تُنشأ بنجاح وتعرض إنشاء المسودة والإرسال والاعتماد مع التطبيق والقيد |
| تتبع دفعة مدخل من الاستلام حتى البيع | يعيد دفعة المورد والدورة والحوض ودفعة الحصاد وأمر البيع في الاتجاه الأمامي |
| تتبع بند بيع إلى الخلف | يعيد دفعة الحصاد والحوض والدورة ودفعة المورد ومرجع الاستلام |
| تجاوز كمية بند البيع أو دفعة التتبع | مرفوض ولا ينشئ تخصيصًا زائدًا |
| استلام مشتريات بلا رقم دفعة مورد | مرفوض قبل إنشاء الحركة أو تغيير رصيد المخزون |
| تعديل وحدة تتبع مباشرة | مرفوض على مستوى SQLite |
| شاشة التتبع التشغيلي | تعرض تسجيل المدخل والاستهلاك والحصاد والبيع وأمري التتبع الأمامي والخلفي |
| نفوق طبيعي بعد تحميل تكلفة المدخلات | لا يخفض رصيد الإنتاج تحت التشغيل وتنتقل التكلفة إلى الإنتاج السليم |
| نفوق غير طبيعي بكتلة 10% من الكتلة قبل الحدث | يفصل 10% من رصيد تكلفة الحوض كخسارة غير طبيعية |
| تحويل كتلة بين حوضين | تنخفض تكلفة المصدر وتزيد تكلفة الوجهة بالقيمة نفسها دون ربح أو خسارة |
| حصاد نهائي من الحوض الوجهة | يُصفّر رصيد تكلفة الحوض ويرسمل القيمة في حركة إنتاج ومخزون المنتج بالتكلفة الفعلية |
| تعديل حدث تكلفة إنتاج مباشرة | مرفوض على مستوى SQLite |
| شاشة تكلفة الإنتاج | تعرض تحميل المدخلات والتكلفة المباشرة والنفوق والتحويل ورسملة الحصاد ودفتر الأحداث |
